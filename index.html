MSE does not apply an empty-edit (elst, media_time = -1) presentation offset

The same media is played two ways in this browser. The video track carries a single leading empty edit (an elst entry with media_time = -1, media_rate = 1, duration 3.0 s) that delays the picture by 3.0 s; the audio track has no such edit. A white flash sits at video media-time 0 and a 1 kHz beep at audio media-time 3.0 s, so the flash lands on the beep only if the offset is applied.

  • Left, MSE. The DASH init + media segments from ffmpeg -f dash are fed through MediaSource / SourceBuffer.appendBuffer (video + audio source buffers). The video init segment contains the elst.
  • Right, direct. The identical media as a progressive file via video.src (a control: Chromium applies the offset here, but Firefox's progressive path also drops it, so judge each player on its own flash vs beep, not against the other).
You should hear a beep from each. In the player that dropped the offset, the beep comes seconds after its flash.
